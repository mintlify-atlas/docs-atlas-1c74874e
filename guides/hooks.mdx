---
title: 'Custom boot hooks'
description: 'Inject custom logic at well-defined points in the wolfBoot boot sequence without modifying wolfBoot source code.'
---

wolfBoot provides a hooks framework that lets you insert board-specific code at key points in the boot process. Typical use cases include custom LED feedback, watchdog management, external hardware unlock, pre-boot diagnostics, and safe-state handling on failure.

Each hook is independently enabled at build time. You only implement the hooks you need — if no hook macros are defined, the boot flow is unchanged.

## Available hooks

| Hook | Macro | Signature | When it fires |
|---|---|---|---|
| Preinit | `WOLFBOOT_HOOK_LOADER_PREINIT` | `void wolfBoot_hook_preinit(void)` | Before `hal_init()` |
| Postinit | `WOLFBOOT_HOOK_LOADER_POSTINIT` | `void wolfBoot_hook_postinit(void)` | After all loader initialization, just before `wolfBoot_start()` |
| Boot | `WOLFBOOT_HOOK_BOOT` | `void wolfBoot_hook_boot(struct wolfBoot_image *boot_img)` | After `hal_prepare_boot()`, before `do_boot()` |
| Panic | `WOLFBOOT_HOOK_PANIC` | `void wolfBoot_hook_panic(void)` | Inside `wolfBoot_panic()`, before halt |

Hook prototypes are declared in `include/hooks.h`.

## Boot flow diagram

```
loader main()
  |
  +-- [HOOK: wolfBoot_hook_preinit()]     <-- WOLFBOOT_HOOK_LOADER_PREINIT
  |
  +-- hal_init()
  +-- other initialization...
  |
  +-- [HOOK: wolfBoot_hook_postinit()]    <-- WOLFBOOT_HOOK_LOADER_POSTINIT
  |
  +-- wolfBoot_start()
        |
        +-- (image verification, update logic)
        |
        +-- hal_prepare_boot()
        |
        +-- [HOOK: wolfBoot_hook_boot()]  <-- WOLFBOOT_HOOK_BOOT
        |
        +-- do_boot()

wolfBoot_panic()  (called on any fatal error)
  |
  +-- [HOOK: wolfBoot_hook_panic()]       <-- WOLFBOOT_HOOK_PANIC
  |
  +-- halt / infinite loop
```

## Enabling hooks

<Steps>
  <Step title="Create your hooks source file">

Create a single C file that implements all the hook functions you want to enable. You do not need to implement hooks you are not enabling.

```c my_hooks.c
#include "hooks.h"
#include "hal.h"

/* Runs before hal_init() — hardware may not be initialized yet */
void wolfBoot_hook_preinit(void)
{
    /* Example: drive a GPIO to signal boot started.
     * Be careful: hal_init() has NOT been called yet. Only use
     * functionality that does not depend on clock or peripheral setup. */
}

/* Runs after all loader init, just before image verification */
void wolfBoot_hook_postinit(void)
{
    /* Example: start a watchdog timer */
    watchdog_start(5000); /* 5 second timeout */
}

/* Runs after verification passes, before jumping to the application.
 * boot_img points to the verified wolfBoot_image struct. */
void wolfBoot_hook_boot(struct wolfBoot_image *boot_img)
{
    /* Example: log the firmware version before handoff.
     * boot_img->part holds the partition ID (PART_BOOT = 0). */
    uint32_t version = wolfBoot_get_image_version((uint8_t)boot_img->part);
    debug_printf("Booting firmware v%u\n", version);
}

/* Runs inside wolfBoot_panic() before the system halts */
void wolfBoot_hook_panic(void)
{
    /* Example: set a safe state, toggle an error LED, notify an
     * external supervisor before the halt loop takes over */
    gpio_set(LED_ERROR, 1);
}
```

  </Step>
  <Step title="Enable hooks in .config">

Set `WOLFBOOT_HOOKS_FILE` to the path of your hooks source file, then enable each hook you have implemented:

```makefile .config
# Path to your hooks implementation
WOLFBOOT_HOOKS_FILE=my_hooks.c

# Enable only the hooks you implement
WOLFBOOT_HOOK_LOADER_PREINIT=1
WOLFBOOT_HOOK_LOADER_POSTINIT=1
WOLFBOOT_HOOK_BOOT=1
WOLFBOOT_HOOK_PANIC=1
```

Each macro is independent. Omit any macro whose corresponding function you have not implemented.

  </Step>
  <Step title="Build">

```bash
make
```

Or pass options directly on the command line:

```bash
make WOLFBOOT_HOOKS_FILE=my_hooks.c WOLFBOOT_HOOK_PANIC=1
```

The build system compiles `WOLFBOOT_HOOKS_FILE` and links the resulting object into the wolfBoot binary.

  </Step>
</Steps>

## Hook-specific notes

**Preinit hook** — fires before `hal_init()`. The MCU clocks and peripherals are not yet configured. Restrict this hook to logic that does not require hardware initialization, such as setting a GPIO that is already in a known reset state.

**Boot hook** — receives a pointer to the verified `wolfBoot_image` struct. You can inspect the firmware version, image type, and other metadata before the jump to application code.

**Panic hook** — fires inside `wolfBoot_panic()` on any fatal error. Use it to set the system to a safe state, toggle error indicators, or notify an external supervisor. The halt loop runs unconditionally after this hook returns.

<Warning>
When `WOLFBOOT_ARMORED` (glitch protection) is enabled, the panic hook is called on a best-effort basis. A fault during hook execution could skip it entirely. The halt loop remains glitch-hardened regardless.
</Warning>
